# UI Audit - 2026-08-31

## Scope

All 13 Web workspaces were rendered from the PostgreSQL-backed local runtime at
desktop (`1440 x 1000`) and mobile (`390 x 844`) viewports:

- Decision: Network, Scenario, Review
- Commercial: Resource Terms, Market, Capacity, Market Positioning
- Analytics: Strategy, Glossary
- Operations: Data Sources, Runtime, Settings, Manual

QA captures are local artifacts under `output/ui-audit/` and are intentionally
not release assets. Selected Image Gen 2 references are committed at
`docs/design/references/market-workspace-imagegen-2026-08-31.png` and
`docs/design/references/strategy-workspace-imagegen-2026-08-31.png`. The later
Operations reference is committed at
`docs/design/references/operations-source-center-imagegen-2026-09-01.png`.

## Findings

1. `AppShell` mounted `NetworkWorkspace` for every page and hid it with CSS.
   Non-network pages therefore retained unnecessary map rendering, overlays,
   and focus targets.
2. The top-bar search only affects network nodes and lines but appeared on all
   13 workspaces, creating a visible control with no effect on 12 pages.
3. Every non-network page repeated the active page and runtime state in a large
   framed title card immediately below the global bar.
4. Adjacent tasks were only available through the full Tools menu, increasing
   navigation cost across Decision, Commercial, Analytics, and Operations flows.
5. The stylesheet contains multiple late responsive overrides. Future page
   redesigns should consume shared shell tokens and primitives rather than add
   page-specific positioning patches.
6. Strategy and Data Sources were the longest surfaces and required subsequent
   task-level information-architecture milestones; those milestones are now
   recorded below.

## Implemented Milestone

- mount `NetworkWorkspace` only for the Network route and mount
  `WorkspaceRenderer` only for non-network routes;
- render the map search only on Network;
- replace the duplicate page/status card with an unframed identity band;
- add directly accessible sibling-page tabs for each workflow group;
- preserve compact, overflow-free mobile stacking;
- keep the full Tools menu as the global navigation entry point.

## Image Gen 2 Interpretation

The reference was generated from the running Market screen. Adopted principles:

- compact shell and immediate operational content;
- quiet separators and aligned dense rows;
- explicit live, runtime, source, and simulation semantics;
- restrained neutral palette with semantic status colors;
- no marketing hero, decorative illustration, nested cards, or oversized type.

The mockup contains illustrative values and must never be treated as market,
capacity, topology, contract, or portfolio data.

## Strategy Milestone

The Strategy workspace was subsequently re-audited against the live runtime.
Its default desktop document measured 4,423 pixels and mounted 15 equal-weight
panels. The implemented task model now provides:

- a persistent command strip for strategy identity, `PAPER`, `SHADOW_RUN`, bar
  duration, observation freshness, no-execution state, and evaluation;
- four accessible task views: Monitor, Economics, Risk & Evidence, and Run
  History;
- a cumulative PnL chart derived only from persisted `strategy_runs` rows;
- focused economics for time-basis, resource-pool, and contract attribution;
- isolated risk controls, quality flags, warnings, and source evidence;
- active-view-only mounting and overflow-free desktop/mobile layouts.

Browser QA reduced the default desktop Monitor surface from 4,423 to 1,334
pixels and from 15 to 6 visible panels. A governed paper evaluation was run
through the local API and persisted to PostgreSQL; the chart and history then
reflected the stored run without producing orders, trades, nominations, or
execution records.

## Operations Milestone

Data Sources and Runtime were re-audited against the running PostgreSQL-backed
application. Before this milestone, Data Sources mounted 24 source rows,
credentials, detail, and infrastructure in one roughly 3,537-pixel document;
Runtime mounted six readiness rows, blockers, commercial sources, database
status, pipeline telemetry, and freshness in roughly 1,939 pixels.

The implemented task model now provides:

- a persistent Sources readiness strip and category posture rail;
- four accessible Sources views: Attention, Catalog, Access & certification,
  and Infrastructure;
- a default queue that prioritizes failed, empty, stale, missing-credential,
  and simulated-substitute sources;
- a licensed-access view that colocates the queue and write-only credential
  controls while preserving explicit effective-source and certification state;
- a persistent Runtime gate strip and three views: Readiness, Delivery, and
  Governance;
- action-led release blockers that open the existing Data Sources workflow;
- active-view-only mounting, keyboard tab navigation, and contained table/tab
  overflow on desktop and mobile.

Browser QA reduced the default Runtime desktop document to about 1,064 pixels
and the default Sources Attention surface to about 1,293 pixels. At `390 x 844`,
the source category rail and task tabs scroll within their own controls, KPI
strips use stable two-column tracks, and the document has no page-level
horizontal overflow. Browser console QA reported zero errors and warnings.

The Image Gen reference contains illustrative values. It does not define source
posture, entitlement, certification, infrastructure records, or release state.
