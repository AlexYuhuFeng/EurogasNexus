# UI Audit - 2026-09-01 EXE Foundation

## Scope

A desktop EXE audit of the shared Web/Windows cockpit at 1707x960 and
responsive checks at 900x1000 and 390x844 identified foundation-level UI
defects in the shared shell, Settings authentication controls, and Review
evidence pack.

Selected Image Gen 2 Direction C reference:

- Repository path (conceptual only):
  `docs/design/references/network-workspace-imagegen-2026-09-01.png`

This reference is a conceptual design direction, not runtime evidence. It does
not define market data, credentials, entitlements, API values, or PostgreSQL
state. All implemented behavior remains API-owned.

## Findings

1. The global header is over-dense and risks collision as width shrinks.
   Controls needed explicit grid areas and deterministic reflow at desktop,
   tablet, and mobile widths.
2. Settings authentication controls were not a semantic responsive grid. The
   release API token label/input, operator principal field, and Save auth
   button ran together at 1707x960.
3. Review evidence status/algorithm/assumptions/source references were rendered
   as run-together text. Long source identifiers had no wrapping rule and were
   unreadable.
4. Typography is generally small, but the audit deliberately avoids broadly
   enlarging dense tables without measured layout QA.

## Implemented Foundation

- Added named grid areas for the shared topbar: workspace, search, trading
  context, and header controls. At 900px and 390px the controls reflow in
  predictable rows without page-level horizontal overflow.
- Rebuilt Settings authentication as `settings-auth-form` /
  `settings-auth-grid` / `settings-auth-field` / `settings-auth-save` with
  separate labels and inputs, password-safe input attributes, stable button
  sizing, and one-column mobile stacking.
- Rebuilt Review evidence pack as key/value rows with
  `review-evidence-grid` / `review-evidence-row` / `review-evidence-key` /
  `review-evidence-value`, plus separate assumption and source-reference lists.
  Long identifiers use `overflow-wrap: anywhere`.
- Added focused contract tests for these semantic classes and responsive
  safeguards.

## Image Gen 2 Direction C Interpretation

Adopted principles:

- stable shared shell with explicit grid areas;
- semantic form rows rather than run-together labels/inputs;
- evidence as key/value rows and separate wrapped lists;
- no marketing hero, gradient, glassmorphism, or decorative cards;
- no broad table typography expansion beyond the audited foundation.

The image reference contains illustrative layout only. It is not a screenshot,
a data source, or an entitlement artifact.

## Browser Evidence

Playwright was run against the local PostgreSQL-backed Web app at:

- 1707x960 (EXE audit width)
- 900x1000
- 390x844

Checks verified no page-level horizontal overflow, no topbar control overlap,
and no Settings auth text collision. Review was checked with a populated
PostgreSQL-backed optimization result; assumptions and long source identifiers
wrapped at all three widths, and no evidence item overflowed its container.

## Network Layout Milestone

The Network workspace now uses a stable map-first shell instead of three
competing fixed/overlay scroll regions:

- desktop >=1280: 320px left resource rail, dominant central map, 340px right
  decision rail, and a non-overlapping bottom resource-path ladder;
- 1101-1279: 280px left rail, 320px right rail, same map-first rows; at
  constrained widths the duplicate trading-context group is removed from the
  top bar so all command controls remain visible;
- 900: map, bottom ladder, resource rail, and decision rail stack in page flow;
- 390: map first, then contained ladder, resource rail, and decision rail.

The right rail uses accessible Decision / P&L / Warnings / Evidence tabs with
active-view-only mounting. ResourcePoolPathOverlay moved from the map overlay
into the bottom ladder and retains the same `resourcePoolMapPaths` data,
allocation, capacity, route economics, warnings, source/geometry evidence, and
empty/blocker states. `LOCAL_MARKET_DISPOSITION` remains non-spatial and is not
rendered as geometry.

Browser evidence was captured with Microsoft Edge at 1440x1000, 1101x960,
900x1000, and 390x844. The desktop evidence was additionally captured at the
packaged-EXE audit width of 1707x960. No page-level horizontal overflow or
topbar/map overlap was measured. The PostgreSQL-backed optimization result was
populated with two paths: a non-spatial local disposition and an indicative
TTF-to-NBP network candidate. Both were visually checked in the ladder, and all
Decision / P&L / Warnings / Evidence views were exercised.

Residual risk: this runtime contains zero verified line geometries, so the
authoritative solid-line rendering branch could not receive populated visual QA.
Its verified-only data gate remains contract-tested. No backend, schema, SQLite,
or API-contract changes were made.
