# ExecPlan: Delivery reconstruction

Status: `in progress`

Owner: repository delivery integrator, with owner-authorized DeepSeek implementation

Related contract: [API evolution policy](../architecture/API_CONTRACT_EVOLUTION_POLICY.md)

## Objective

Reconstruct missing cloud work and complete source-to-consumer business workflows
with independent numerical, permission, runtime and release verification.

## Scope and boundaries

Capacity billing, LNG energy/economics and terminal reference contracts; their
API, SDK and existing Web workflows; source adapters and provenance; contextual
research workflows and final Windows/Linux delivery. Preserve existing API and
PostgreSQL authority, security and licensing controls. No trade execution,
nomination or settlement. No candidate fact silently becomes reviewed data.

## Work sequence

1. Recover and independently review missing calculations and strict refusals.
2. Add compatible typed API/SDK and usable bilingual existing-workspace flows.
3. Integrate lawful official data with exact source/time/unit provenance.
4. Verify distinct roles, real HTTP, browser business tasks, performance and
   artifacts built from final committed source. Push reviewed checkpoints.

## Verification and acceptance

Focused domain/API/SDK tests, numerical golden and hostile-context regressions,
contract census, full regression suites, dedicated PostgreSQL, real HTTP/SDK,
browser tasks and native installed artifact evidence are required. Current
completion evidence and outstanding gates live in
[delivery recovery register](../release/acceptance/23_DELIVERY_RECOVERY_AND_GATES.md).
The capacity endpoint alone is not full route/portfolio acceptance.

## Rollback and risks

Additive endpoints and pure primitives require no migration; revert a bounded
commit if needed. Do not revert unrelated source/security work. Unknown tariff
applicability, provider access, licensing, reviewed reference facts, production
SSO and final artifact signing remain explicit gates, never inferred success.
